## Pattern Watch
No prior tape here, but this repeats three confirmed Superman lessons:
- **09-27 "Shipping is deploying, not pushing — speed is never bought from the gates."** A public push is shipping; the gates were skipped anyway.
- **09-27 "A gate you never encountered is not a gate you passed."** Here the gates literally couldn't fire — Scout runs outside the hooks — so silence meant nothing, exactly as warned.
- **10-06 "In a repo with live credentials, anything you output is published."** Generalises cleanly: anything you *push* is published. The same class of slip, new tool.

**Root cause:** a public push was treated as "just a personal tool," so no `/decide` and no active-task were declared, so no harness gate fired — and Scout sessions bypass the Claude Code hooks entirely. The constraint is real: the harness assumes work flows through tools it instruments. It doesn't.

## Constraint Health
No hook blocked anything it shouldn't have — the problem is the opposite. The entire gate is invisible to Scout. Enforcement that lives only in Claude Code hooks cannot protect a push that originates in Scout, Copilot, or raw `git`. This is a coverage gap, not over-blocking.

## Sharpened Lessons (for Superman)
1. **[2026-11-05] A public push from ANY tool is shipping — gate it before the first push:** Scout, Copilot and raw `git` all bypass the Claude Code hooks, so "no warning fired" is meaningless outside Claude Code. Before the first push of any repo that is or will be public, run Kryptonite and Vera by hand; the critical K-01 was found only by the red team, never by 14 self-authored tests. [source: tape 2026-11-05]
2. **[2026-11-05] Read the product's own logs as test evidence:** K-01 was visible for hours as a flood of "Too short, ignored" lines in Steve's live log from ordinary Ctrl+C/V. The signal was on disk before the red team opened the file. Treat the running product's own log as a first-class test oracle, not noise. [source: tape 2026-11-05]
3. **[2026-11-05] When the target is the user's own machine, sandbox by path, not by name:** The installer and its process-kill matched `voice_anywhere.py` as a command-line substring and took down Steve's live instance. Installers and tests that run against the user's real machine must scope every match (kill, env override, cleanup) to the install *path*, and the tester must verify the user's live state is byte-identical before and after. [source: tape 2026-11-05]
